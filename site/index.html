Which rooms of an AI-drawn floor plan can you trust?

PlanTrust compares every room of the plan with the 360-degree tour of the same house. Rooms that agree are accepted. Rooms that do not agree go to a human drafter, with the reason and the dollars at risk.

A demo by Hossam El-Kharbotly, built for my application to the Senior Software Engineer, AI Agents role at DocuSketch. It uses only synthetic houses, so every number here comes from scripts you can rerun with one command.

Why I built this

  • The floor plan drives the estimate. Wall lengths, floor area and ceiling height become the quantities that are priced in Xactimate, so a wrong wall means a wrong price.
  • Instant Sketch is fast, and its weak spots are known. DocuSketch's own material names stairwells, tall ceilings and glass walls, and notes that reflective surfaces can create objects that are not there.
  • Drafters are the expensive, slow step. Sending every plan to a human throws away the speed; sending none puts wrong quantities into claims.
  • So the useful question is narrower: which rooms of this plan can be trusted, which need a drafter, and what would an error cost?

How it works

  1. Plain-code checks

    Walls close, rooms do not overlap, the plan agrees with the tour measurements. Clear cases are decided here, exactly and for free.

  2. A small agent, only for unclear rooms

    One model with 4 tools (read the room, read the tour, read the check results, submit a verdict) decides: accept, or send to a drafter.

  3. Cost at risk per room

    How many dollars a wrong area or height would move, from two illustrative price items.

The result is one verdict per room: accept, or send to a drafter with the reason and the dollars at risk. Code goes first because it is exact and free. The agent sees only the rooms code cannot settle. When the agent is unsure, fails, or runs out of steps, the room goes to a human; it can never accept a room by failing.

One failure, one fix

From trusted plan to draft estimate

Part 2 takes a room PlanTrust trusted and drafts its mitigation line items. The quantities come from the floor plan, the choice of items comes from past jobs and the technician's scope notes, and every item shows its evidence.

In production, prices come from Xactimate through the existing Verisk integration. This demo uses a mock price source with example prices, because real Xactimate price lists are licensed. The agents do not change; only the price source does.

Limits, and what I would do with real data

  • Synthetic houses of rectangular rooms, with errors I planted myself. It shows the method, not real-world accuracy.
  • Simulated tour measurements with simple noise (about 2% on walls, 0.3 ft on ceilings, door counts sometimes off by one). Real tours are messier.
  • Illustrative prices for two items (wet drywall removal, drying fans by the IICRC (Institute of Inspection, Cleaning and Restoration Certification) rule of thumb). They are not real price lists.
  • The estimation agent over-includes. It finds far more of the real items and most of the often-missed ones, but it also adds extra items a human must strike out. Tuning that trade-off (for example, requiring a note or a strong history share for each item) is the next step, measured on a fresh held-out set rather than the one shown here.
  • Many of the review agent's decisions could be written as code rules, now that the failure-and-fix spelled them out. That is the point of the exercise: the agent earns its place where the evidence is mixed, and every rule it reveals can move into code.
  • Model: Mistral voxtral-small-latest on Mistral's free mode, chosen because it was the one model with a usable free allowance on this account. A stronger model would likely do better; the harness, the tests and the scoring stay the same.
  • With real data I would build the test set from drafters' corrections, use the vision team's real outputs as input, add every miss as a test case, and let the agent decide alone only where the numbers prove it is safe.
